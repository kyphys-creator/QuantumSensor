# quantum_sensor (TES_clean2)

Dark-matter quantum-sensor response analysis, rebuilt around the new
Mathematica response matrices (`../Mathematica/output/TES/response_matrix/`).

## Pipeline

```
response matrix M  (Mathematica 10)        eta(v_min)   (halo model)
   matrix/vmin/bins.csv                          |
            \                                     |
             \---> forward:  observed = exposure * M @ eta  (+ background)
                              |
                   inverse:  recover monotone, non-negative flux x that
                             reproduces the observed energy-bin counts
                              |
                   plot:  input eta vs recovered staircase flux
```

The forward+inverse is **self-consistent**: the observed counts are generated
from the matrix and the chosen `eta`, and the inversion recovers a piecewise
flux that reproduces them.

## Design: no magic numbers

* shapes, energy bins and the v_min grid are read from the matrix files
  (`matrix.csv`, `vmin.csv`, `bins.csv`) -- never hard-coded;
* physical constants live once in `constants.py` (sourced from Mathematica
  `01_setup` / `05_parameters`);
* the exposure scale `K` is derived (`constants.AL_EXP`), and the solver
  conditioning (old `cons1`/`cons2`) is computed from the data in
  `model.condition` -- nothing is hand-tuned. The recovered flux *shape* is
  independent of `K`.

## Modules

| module | role |
|--------|------|
| `config.py` | `RunConfig`, `BackgroundModel`, `BACKGROUND_SCENARIOS` |
| `constants.py` | physical constants (single source) |
| `data_loader.py` | read new matrix folders + legacy eta/ratebin |
| `model.py` | eta alignment, forward operator, data-derived conditioning |
| `backgrounds.py` | scenario backgrounds on the matrix's energy bins |
| `optimizer.py` | monotone non-negative chi-squared / QP solvers (reused) |
| `analysis.py` | `DarkMatterQuantumAnalysis(config)` -- the entry point |
| `plotting.py` | eta-vs-recovered-flux figure + CSV export |

## Usage

```python
from quantum_sensor import DarkMatterQuantumAnalysis, RunConfig

a = DarkMatterQuantumAnalysis(RunConfig(material="Al", q="0", mass="3",
                                        nbins=5, eta="Halo", background="none"))
flux = a.optimize(solver="osqp")   # recovered flux on a.vmin_mid
a.plot()                            # save comparison figure
a.save_flux()                       # save flux + v_min grid as CSV
```

`q="0"` heavy / `q="2"` light mediator; `mass="1|2|3"` = 10 MeV / 100 MeV /
1 GeV; `nbins=5|10`. See `examples/run_example.py`.

> Scope: TES (Al). The legacy `data/` folder (eta, ratebin) and the old
> `curlyRplotting` matrices are kept for cross-checks. R10 / q2 work; the
> observed counts are generated by the self-consistent forward model rather
> than the legacy 5-bin Ratebin.
